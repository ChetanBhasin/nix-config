Prepare and carry out the authorized experiment: ${@:-the current accepted experiment}.

1. Freeze the hypothesis, primary user metric, baseline, dataset/live source, horizon, sample size, uncertainty, resource limit and stopping rule before running it. Define the final report schema now and populate it as evidence arrives.
2. Record all mandatory outputs in `workflow_contract`, including any interactive report, presentation, slides or video. Pin reproducible interface calls and relevant external inputs. Distinguish source inspection, offline replay, synthetic traffic and actual live behavior.
3. For trading, load `kraken-experiment-contract`: optimize net PnL/risk after fees/slippage, not predictive accuracy alone. A campaign does not authorize real orders. For performance work, record workload, machine, revision, build profile and concurrency; do not turn a narrow benchmark winner into a universal claim.
4. Claim the exact writing roots and use required shell permits. Use a single writer and Astra/max for substantive reasoning. Use Rust harnesses in Rust repositories; existing healthy tooling remains valid. Justify any disposable Python analysis and do not promote it into the acceptance path without deliberate approval.
5. Keep raw runs, logs and temporary state outside source roots. Record a campaign manifest linking configuration, timestamps, revision, data provenance, seeds where relevant, output paths and known gaps. Do not expose secrets or disturb unrelated processes.
6. Inspect the actual generated report/artifact and run the relevant user journey. Report missing samples, unsupported conclusions and failed gates as incomplete. Stop at the declared boundary; expanding cost, scope or protected actions needs authority. Complete only with checked evidence.
