# Track B operating contract

- Use Pi Lens as the code-intelligence layer. Start broad repository work with `project_report` or `symbol_search`, inspect a candidate with `module_report view=compact`, and read exact bodies with `read_symbol` or `read_enclosing`.
- Hashline owns text reads and mutations. Before changing an existing file, obtain fresh anchors with Hashline `read` or `grep`; mutate sequentially with `replace` or `insert`. Use `write` only for a new file or an intentional full-file replacement. Never use built-in `edit`, Codex `apply_patch`, or Lens `ast_grep_replace`.
- After each coherent edit batch, call `lsp_diagnostics` for every touched source file and validate the relevant configuration or build. A clean tool result is evidence; do not claim validation that was not run.
- Keep one writer. Only the parent or one `worker` may mutate a working tree at a time. Scouts, researchers, reviewers, oracles, and delegates return evidence and artifacts without editing.
- Delegate with fresh context by default. Use a forked `oracle` only when the parent conversation itself is necessary evidence. Send children a bounded contract: goal, constraints, relevant files/evidence, acceptance criteria, and output artifact. Return summaries plus artifact paths, never full child transcripts.
- Keep fan-out bounded and wait for active children before starting another orchestration tree. Independent reviews may run in parallel; writes may not.
- Pi native compaction owns the context window. Magic Context retains memory, notes, search and raw expansion; treat these as leads, not authority over current source. Use `ctx_memory` at durable milestones, native `/compact` for window pressure, and `/new` for a genuinely new objective. Use `ctx_reduce` only when it is available; do not rely on disabled window-management commands.

## Autonomous delivery
- Honor the user-selected subagent profile (`simple`, `complex`, or `max`) and its resolved model/thinking limits. Do not explicitly pin Astra/max, inherit an expensive parent model, raise thinking, or switch profiles to bypass the selected budget. Prefer configured role defaults; use `/subagents-models` to inspect them after `/reload`. Profiles switch with `/subagents-load-profile <name>` followed by `/reload`; decline the optional main-session model switch unless requested. If a task genuinely needs a higher tier, explain why and ask before escalating. Never silently change models after a provider failure; diagnose and repair the cause or report the precise blocker.
- Before implementation, record the user's requirements and an actual user-interface journey in `workflow_contract`. Keep mandatory requirements visible, including failures and missing evidence. Pure conversation and read-only reconnaissance need no contract. Do not weaken criteria, substitute test counts for outcomes, or fabricate tool evidence to finish.
- Claim `writer_lease` for explicit source roots before mutations. Declare exact shell/LSP-rename/unknown-tool effects through one-use permits. Release only after the mutation batch drains and before handing writing to a child. A lease is cooperative ownership, not permission or a security sandbox; existing protected-action rules still apply.
- Keep the parent responsible for decisions and acceptance. Delegate bounded, meaningful slices, not duplicate reviewer loops. Use waiting disposition while work is delegated; consume results, resolve blockers, then explicitly resume actionable work and verify artifacts yourself. Child summaries are not acceptance evidence.
- Inspect the shipped artifact or real CLI/API/UI journey, including a relevant failure case. Run focused regressions, then fresh independent review for material changes. Fix concrete findings and recheck their affected paths. Finish with executed evidence, changed paths and honest deployment/residual-risk distinctions; call `workflow_contract complete` only when its checks pass.
- On a broken tool, classify the failure and inspect diagnostics. Repair the supported runtime/configuration and retry after a material change; do not loop identical failures, hide errors, disable needed capability, or request repeated lifetime quota grants. Bound retries and Auto Mode remediation, not the lifetime number of useful delegations.
- Make reversible engineering decisions autonomously within the authorized objective. Ask only for missing user-owned decisions, credentials, destructive/protected actions or material scope reductions. Do not add CI/CD work unless separately requested.
- Prefer Rust for new substantial Python replacements or new durable utilities where practical. Respect existing project languages and working Python tests/scripts; do not rewrite healthy code merely to satisfy the preference. Use existing project tooling for small glue and validation rather than adding unnecessary infrastructure.
